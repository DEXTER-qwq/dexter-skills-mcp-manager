MCP 停用为什么不用改配置

// 1) 从状态里取出被停用的 serverName
// 2) 只 deny「当前真实注册」的工具名 —— restrict() 对未知名字会抛错
const deny = denyNamesForDisabled(disabledNames, tools.schemas())
// 3) deny 集合没变就绝不重复 restrict：
//    restrict() 会同步触发 tools/change，而监听器又会回到这个函数，
//    不比较就会无限递归，把整个进程卡死（参考实现踩过这个坑）
if (current && current.deny.join('\0') === deny.join('\0')) return
// 4) 有变化才换层：老手 agent 作用域，只影响这一个 agent
const disposer = agentCtx.get('tools').restrict({ deny })
为什么 apply() 必须是同步的？ Cordis 把带 prototype 的函数当构造函数，会忽略它返回的 promise。于是 async apply 里 await 之后抛的错会变成 unhandled rejection，可能直接拖垮整个 dsh 进程。所以插件只做同步注册，异步的挂载/restrict 都放在 effect、事件回调或请求里。
能力缺失时降级，不报错。 如果宿主组合里没有 loader / tools，页面显示「能力不可用」并照常列出当前状态，而不是抛错或空白。

残留的信任边界（说清楚，不粉饰）

  • 插件本身与 dsh 同权。 通过 dsh plugin add 装进来的代码能以你的身份读写文件。这次改动缩小的是「插件自身代码里有没有危险链路」，不是「插件机制是否隔离」。
  • MCP server 是本地程序。 在 MCP 管理页新增一条 stdio server，等于让 dsh 启动你指定的命令——这和手写一行 dsh 配置的权限完全相同，页面只是把它做得更方便。不确定来源的 server 不要加。
  • 本机 HTTP 路由无独立鉴权。 沿用 webServer 的现有边界；新增/删除/开关 MCP 都走这个路由，能访问该端口就能改 MCP 配置。
  • devDependency 仍在。 @deepseek-ai/schemastery 是 dsh 官方包，仅供 settings schema 注册，缺失时自动跳过；它不进运行期依赖。
