它是怎么接进 dsh 的

宿主进程（插件宿主半）
·skills → 注册 1 个 provider，把用户库技能喂给模型
·webServer → 挂 /skills-management/api 路由
·settings → 执行器目录覆盖的持久化
·loader → 读已有的 MCP 条目 / 把手写配置里的 server 挂上去
·tools → 只用来数每个 server 的真实工具数
客户端（浏览器半）
·settings.section × 2 → 侧栏「技能管理」「MCP 管理」
·conversation.input.left → 输入框「＋技能」按钮
·locale → zh / en 全量文案
·只用 ui-theme 的 --dsw-* token，无硬编码颜色

两个数据流

技能：读文件系统
→扫描 16 个执行器目录（~/.claude/skills …）
→读 SKILL.md，自写读取器解析 frontmatter
→收编：复制进 $DSH_HOME/skills
→治理：改写 disable-model-invocation（原子写）

只动技能目录，不碰 dsh 配置。

MCP：读 loader + 你的手写配置，只写自己的状态文件
→列表：loader.entries() + mcp.local.jsonc，同名出一条
→挂载：loader.create()，id 前缀 sm-mcp-
→开关：只把文件里 "enabled": false 的条目打开
→状态：$DSH_HOME/skills-management/mcp.json（只放一个 forcedOn）

不解析、不改写 dsh 的任何 YAML，也不改写你的手写配置。

为什么开关只能「开」不能「关」

「关掉一条 server」必须写在声明它的那个文件里。本插件能写的只有自己的状态文件，而状态文件里一个名字的缺席只能表示「没被覆盖」，不能表示「关」——所以页面只做它能兑现的那一件事：把手写配置里 "enabled": false 的条目强制打开，并记下这份覆盖。

// 手写配置（mcp.local.jsonc）——只有你写，插件从不改写
{ "serverName": "ssh-mcp-server", "command": "npx", "args": ["-y", "@fangjunjie/ssh-mcp-server"], "enabled": false }
// ↑ 页面上点「启用」之后，插件自己的 mcp.json：
{ "forcedOn": ["ssh-mcp-server"] }
// 条目本身、注释、尾随逗号都原样保留；点「停用」就把名字从 forcedOn 里删掉。
// 没写 enabled:false（也就是开着）的条目页面上不画开关：要关只能回文件里改。
为什么 apply() 必须是同步的？ Cordis 把带 prototype 的函数当构造函数，会忽略它返回的 promise。于是 async apply 里 await 之后抛的错会变成 unhandled rejection，可能直接拖垮整个 dsh 进程。所以插件只做同步注册，异步的挂载都放在 effect 的 fire-and-forget 或请求里。
能力缺失时降级，不报错。 如果宿主组合里没有 loader / tools，页面显示「能力不可用」并照常列出当前状态，而不是抛错或空白。

安全审计结论

对上游 0.6.1 全量源码逐文件读过、依赖实际装下来读过之后的结论。

没发现「藏起来的」恶意载荷。 没有 eval / new Function / 混淆代码 / 硬编码外发地址 / 后门凭据 / 读取 SSH 私钥或批量外传环境变量。GitHub workflow 是正规的 npm Trusted Publishing（OIDC，无 NPM_TOKEN）。

残留的信任边界（说清楚，不粉饰）

  • 插件本身与 dsh 同权。 通过 dsh plugin add 装进来的代码能以你的身份读写文件。这次改动缩小的是「插件自身代码里有没有危险链路」，不是「插件机制是否隔离」。
  • MCP server 是本地程序。 在 MCP 管理页新增一条 stdio server，等于让 dsh 启动你指定的命令——这和手写一行 dsh 配置的权限完全相同，页面只是把它做得更方便。不确定来源的 server 不要加。
  • 本机 HTTP 路由无独立鉴权。 沿用 webServer 的现有边界；新增/删除/开关 MCP 都走这个路由，能访问该端口就能改 MCP 配置。
  • devDependency 仍在。 @deepseek-ai/schemastery 是 dsh 官方包，仅供 settings schema 注册，缺失时自动跳过；它不进运行期依赖。

验证与卸载

dsh plugin why dsh-skills-mcp-manager

改过包名要重新注册一次。本 fork 从 @weibaohui/skills-management 改名为 dsh-skills-mcp-manager（0.7.0-local → 0.8.0-local），而 profile 里记的是旧包名：先 dsh plugin remove @weibaohui/skills-management，再 dsh plugin add "D:\11dsh\skills-management"，然后重启 DSH。若 ~/.dsh/profiles/desktop/cordis.patch.yml 里还留着 id: skills-management 的残留行，删掉它。

卸载插件不会删掉 ~/.dsh/skills-management/ 目录（mcp.json 记着你的覆盖，mcp.local.jsonc 是你的手写配置）。想彻底清干净，手动删掉那个目录即可。
